# FQL-POL-0002 — Паспорта артефактов и полный цикл доказательств

## Решение

В FATHER Quant Lab результатом считается не только код или доходность. Для каждого
значимого артефакта и прогона сохраняется доказательная цепочка:

`IDEA → SOURCE → HYPOTHESIS → REQUIREMENT → DESIGN → CODE → TEST → RUN → RESULT → CRITIQUE → DECISION → LESSON`

Если звено отсутствует, работа не считается полностью завершённой. Неудачные
гипотезы и отрицательные результаты не удаляются: они защищают от повторения ошибок.

## Два уровня паспортов

### 1. Паспорт артефакта

Используется для ТЗ, набора данных, программы, стратегии, теста, отчёта, модели и ADR.
Минимальные обязательные поля:

| Поле | Назначение |
|---|---|
| `artifact_id` | Стабильный шифр |
| `artifact_type` | Тип объекта |
| `purpose` | Зачем создан |
| `owner_role` | Аналитик, программист, тестировщик или риск-контролёр |
| `source_basis` | Книга, статья, решение, ТЗ или исходная идея |
| `inputs` / `outputs` | Входы и результаты |
| `relations` | Связанные требования, код, тесты и решения |
| `version` / `sha256` | Версия и контроль целостности |
| `status` | Стадия жизненного цикла |
| `limitations` | Что объект не доказывает |
| `verification` | Чем и когда проверен |
| `decision` | Принят, отклонён, требует доработки |
| `lessons` | Что передаётся следующим разработкам |

### 2. Паспорт прогона

Создаётся автоматически рядом с полным JSON-отчётом. Он содержит:

- исходную идею и проверяемую гипотезу;
- требования и ADR;
- реализацию и тесты;
- SHA-256 набора данных и отчёта;
- seed, среду исполнения и ограничения безопасности;
- метрики каждого робота;
- отдельно: что доказано и что **не доказано**;
- решение, уроки и следующий контрольный рубеж.

## Правило полноты

Большие фактические данные хранятся один раз в исходном артефакте. Паспорт хранит
их SHA-256, путь, схему, происхождение и итоговую интерпретацию. Это сохраняет полный
объём доказательств без неконтролируемого дублирования многомегабайтных файлов.

Консольный вывод сам по себе доказательством не считается. Он должен быть сохранён
в отчёте, тестовом протоколе или журнале инцидента и связан с паспортом.

## Роли

| Роль | Заполняет |
|---|---|
| Аналитик | идея, источник, гипотеза, требования, критерии успеха |
| Архитектор | схема, границы, ADR, угрозы и ограничения |
| Программист | реализация, зависимости, версии, известные ограничения |
| Тестировщик | тесты, среда, фактический результат, дефекты |
| Риск-контролёр | допустимость, kill switch, запреты и остаточный риск |
| Критик | контрпример, альтернативное объяснение, защита от переобучения |

## Статусы

`idea → specified → implemented → tested → reproduced → challenged → accepted/rejected → golden-pattern`

Переход выполняется только по зафиксированному доказательству. Доходность никогда
не заменяет корректность данных, реалистичность исполнения и независимую проверку.
