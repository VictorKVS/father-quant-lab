# FQL-S6-REG-001 — причинные режимные метки

## IDEA → SOURCE → HYPOTHESIS

Идея следует обязательному анализу ошибок по режимам из
`docs/research-methodology.md`. Гипотеза: минимальный объяснимый классификатор может
создать воспроизводимые метки без обращения к будущим барам и без торговых выводов.

## Требования

1. Только закрытые бары до и включая время метки.
2. Warm-up равен lookback; до него меток нет.
3. Параметры положительны и записываются в отчёт; `optimized=false`.
4. Trend: `UP`, `DOWN`, `RANGE`; volatility: `HIGH`, `NORMAL`.
5. Метка содержит timestamp и `available_to_system_at`.
6. Dataset остаётся `MODELLED` и связан SHA-256.
7. Regime truth, performance, PAPER и LIVE claims запрещены.
8. Повторный запуск создаёт идентичный JSON.

## Критерии приёмки

- тестируется warm-up, три trend-ветви, неверные параметры и причинность;
- будущий экстремальный бар не меняет уже созданную метку;
- CLI на 12 барах с lookback 5 создаёт 7 меток;
- все safety flags закрыты;
- полный набор тестов, `compileall` и `git diff --check` проходят.

## Риски и границы

Фиксированные пороги не откалиброваны на реальном EUR/USD. RMS — не годовая
волатильность. Метка не учитывает spread, события, ликвидность и смену сессий.
Прототип доказывает только интерфейс, детерминизм и временную причинность.
