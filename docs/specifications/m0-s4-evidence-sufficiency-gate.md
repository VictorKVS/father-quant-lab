# FQL-S4-SUFF-003 — минимальная достаточность участка

## IDEA → SOURCE → HYPOTHESIS

Источник — критика результата `RUN-M0-S4-PLAN-20260816` и требование проекта не
повышать зрелость по формально зелёному файлу. Гипотеза: отдельный gate обнаружит
участки, которые структурно корректны, но короче warm-up стратегии.

## Требования

1. Не изменять sealed plan и прежний результат.
2. Критерии имеют стабильный ID и статус `PRE_REGISTERED`.
3. Lookback определяется как максимум положительных `*_window`.
4. Каждый TRAIN/VALIDATION/OOS имеет собственный warm-up.
5. Требуемое число баров: `lookback + minimum_scored_bars_per_split`.
6. Недостаток рассчитывается отдельно для каждого участка.
7. Положительный механический результат не доказывает статистическую достаточность.
8. PAPER, LIVE и performance claims остаются закрыты при любом результате.

## Критерии приёмки

- текущий sample даёт дефицит 21 бар на каждом участке;
- искусственный позитивный путь 25/25/25 проходит только mechanical minimum;
- отсутствие окна, draft-критерии и неверный bar count блокируются;
- CLI создаёт детерминированный JSON;
- полный набор тестов, `compileall` и `git diff --check` проходят.

## Риски и границы доказанности

Число 20 — engineering smoke threshold, а не вывод рынка или статистики. Gate не
оценивает автокорреляцию, режимы, частоту сделок, transaction costs, multiple
testing или power. Исторические пороги появятся новой версией критериев после S2.
