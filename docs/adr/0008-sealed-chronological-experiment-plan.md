# ADR-0008 — sealed chronological experiment plan

## Статус

Принято для подготовки M0/S4; dataset и performance gates остаются закрыты.

## Контекст

Разделение train/test, записанное после просмотра результата, не защищает от
переобучения. Календарный разрыв также нельзя считать embargo автоматически:
проверка должна считать реально пропущенные бары.

## Решение

До оценки стратегии фиксировать JSON-план с SHA-256 данных, классификацией,
инструментом, параметрами, последовательностью `TRAIN → VALIDATION → OUT_OF_SAMPLE`,
числом embargo-баров и закрытым доступом к OOS. Валидатор работает fail-closed,
требует границы на существующих барах и запрещает пересечения.

Этот gate проверяет структуру исследования, но не лицензию или качество данных.
Даже корректный план всегда возвращает `performance_claim_allowed=false` на данном
уровне зрелости.

## Альтернативы и последствия

- Случайный split отклонён: он разрушает временной порядок.
- Автоматический подбор пропорций отклонён: план должен быть предрегистрацией.
- Разрешение OOS во время разработки отклонено: возникает адаптация к тесту.
- Purged cross-validation отложена до данных и стратегий со сложными метками.

Плюс — нарушение плана видно машинно. Минус — короткий MODELLED sample проверяет
только gate и не может служить оценкой стратегии.
