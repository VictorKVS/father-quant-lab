# ADR-0013 — независимый Decimal-oracle для режимных меток

## Статус

Принято для механической cross-check проверки pre-S6; зрелость данных не повышается.

## Контекст и решение

Unit-тесты основной реализации могут повторять её ошибочное понимание формулы.
Поэтому контрольный расчёт не импортирует `regimes.py` или генератор баров из
`stress_scenarios.py`. Он отдельно восстанавливает closes из bps, использует
50-значный `Decimal`, `ln` и `sqrt`, затем сравнивает семь полей каждой метки.

Для двух float-метрик заранее установлен абсолютный допуск `1e-12`; категориальные
поля, timestamps и lookback должны совпасть точно. Расхождение даёт сохраняемый
`BLOCKED_CROSSCHECK_MISMATCH`, а несовпадение ID или SHA входа прекращает проверку.

## Альтернативы и последствия

- Ещё один тест той же функции — отклонён как не независимый.
- Внешний framework — отложен до допуска исторических данных и cross-engine S6.
- Требовать битового равенства float и Decimal — отклонено из-за разной арифметики.
- Считать совпадение доказательством истинности режима — запрещено: обе реализации
  проверяют один зарегистрированный контракт на искусственных путях.
